# Surface: Hum-to-Search app (index.html, src/App.tsx)

Mode: Operate. Audience: DSA course demo (team presenting, instructor + class watching, often projected); secondary any visitor. Task: hum (or play a demo hum / keyboard) and watch the song resolve while the trie and red-black tree do visible work. Constraints: non-mic input path required; reduced motion; status never colour-only.

## Direction contract

THESIS: The hum is a punched music roll and the search is the roll being read. Refuses the dark neon audio dashboard with glowing waveform and card grid.

OWN-WORLD: Manila roll-paper ground, dark walnut-ink shell rail, punched slots as the only "data mark". Roll-leader inks do the jobs: leader green = the track being followed (current lead, live trie paths), vermilion = red-black red nodes and torn (pruned) branches, gold = confidence. One workhorse grotesque (Archivo, width axis for condensed roll-label headings), mono only for interval code and numbers. Hairline rules and perforation edges divide areas; no cards, no glass.

STORY: Viewer sees notes punched as they are hummed, sees the trie's paths stay inked or tear away, sees the leaderboard reorder and the meter fill; believes the structures did the identification; can run it themselves.

FIRST VIEWPORT: Top bar: name, input source tabs (Microphone / Demo hum / Keys / Recording; Recording added because the deliverables include a demo recording and graders need a non-mic path that uses real audio), primary Start button. Left 2/3: the Roll (tracker-bar waveform strip above a scrolling pitch roll with punched slots, interval code row under it), Trie explorer below. Right 1/3: Confidence first (locked in, it becomes the roll-leader label naming the tune, the payoff a projected room reads first), then Leaderboard top 5, then the red-black tree. The roll sheet is --paper-hi, paler than the manila page, so punched holes keep full contrast.
